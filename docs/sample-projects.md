# 示例项目说明

TextFlow 在首次打开空工作区时，会自动创建 9 个官方场景样例项目。它们不是前端预渲染 demo，而是由 Python sidecar 基于真实公开数据缓存生成的 `.tfproj` 项目，用来验证真实语料、真实词表和真实 workflow 能否从打开项目一路跑到导出。

更完整的数据来源、许可证和样例矩阵见 [内置场景样例](./examples.md)。

## 生成规则

- 触发条件：第一次加载空工作区。
- 生成位置：用户工作区的 `projects/`。
- 默认当前项目：官方样例集合中的第一个可用项目。
- 运行状态：创建时不预跑分析，用户需要手动运行 workflow。
- 数据来源：`services/python-engine/app/public_sample_cache/` 中的公开数据缓存。
- 语言配比：每个官方样例保持严格英中 `1:1` 行数配比。
- 默认规模：示例 01 为 `20,000` 条，其余 8 个示例为 `10,000` 条。

## 示例项目有什么价值

- 帮助新用户快速理解 `.tfproj` 项目里会保存什么。
- 让用户在没有自有数据时也能跑通导入、词表、workflow、分析和导出链路。
- 帮助开发者用真实数据验证节点执行、缓存、运行历史、artifact preview 和导出行为。
- 让停用词、同义词、标准词和排除词等规则在真实语料上暴露问题，而不是只在单节点单元测试里通过。

## 开发与测试时降低规模

如果只是本地 smoke test，可以临时设置：

```powershell
$env:TEXTFLOW_SAMPLE_PROJECT_ROW_LIMIT = "120"
```

这个值必须是偶数，系统仍会保持英中 `1:1`。测试结束后可执行：

```powershell
Remove-Item Env:TEXTFLOW_SAMPLE_PROJECT_ROW_LIMIT
```

## 当前边界

- 官方样例文本来自真实公开数据，可能包含噪声、旧术语、重复表达或来源风格差异。
- 样例创建时不自动生成结果，第一次结果需要用户手动运行 workflow。
- 已有用户项目的工作区不会重复注入官方样例。
- 大规模样例会真实占用磁盘和运行时间；性能验证时应关注项目目录、run 目录和导出目录的体积变化。
