# 产品范围与完成度

本文档以 AGENTS 和当前产品目标为基线，逐项对照仓库现状，明确哪些已经落地，哪些仍是边界或后续工作。

## 产品目标

- 稳定可交付优先于炫技功能
- 以项目为中心组织数据、词表、流程、输出和运行历史
- 预处理流程可复跑、可审计
- UI 不阻塞长任务
- 为后续更强的节点式编排保留扩展位

## 与 V1 目标对齐但超出原始骨架的能力

这些不是最初骨架阶段就有的，但现在已经进入仓库主链：

- workflow 画布已经成为主流程入口
- `workflow_definitions + active_workflow_id` 已写入项目模型
- manual/template workflow 已可走 native DAG
- 节点缓存和节点级运行摘要已接入
- 语料资源、语料视图、导入规格、artifact records、review tasks 和 experiment specs 已写入项目模型
- 桌面端已提供 Resource Browser、Artifact Browser、Review Queue、Experiment Matrix 和 Run Diff surface
- 本地纯 Python 插件节点已可被 sidecar 扫描并注册
- 首次启动自动生成 9 个场景样例项目，覆盖从预处理、词表治理到复核、门禁的完整 workflow surface

## 当前仍不算“已交付完成”的部分

| 主题 | 当前判断 | 原因 |
| --- | --- | --- |
| Windows 发版质量 | 仍需收敛 | 安装包链路已配置，但缺少持续 release 验证和分发流程说明。 |
| macOS 兼容性 | 未验证完成 | 代码层尽量保持可移植，但没有正式构建与测试闭环。 |
| workflow 产品化体验 | 部分完成 | 核心能力已有，但交互、文案、调试体验和用户理解成本仍需打磨。 |
| 前端测试体系 | 未完成 | 当前主测试面在 Python 引擎。 |
| CI / 自动回归 | 未完成 | 仓库里没有成体系的 CI 配置。 |

## 明确的非目标

以下内容仍不属于当前 V1 交付范围：

- 拖拽式节点市场或云端模板市场
- 云同步
- 多用户协作
- 移动端 App
- 跨项目 artifact registry
- 面向终端用户的局部重跑和 dirty 传播 UI

## 当前建议的交付口径

如果以“现在这个仓库可以对外怎么描述”为标准，更准确的口径应该是：

> TextFlow 已具备一个可运行的桌面端文本处理与基础挖掘闭环，V1 目标能力基本齐备，同时已经提前接入 workflow 画布、native DAG 和插件节点这些面向后续版本的基础设施；但在前端测试、CI、安装包验证和 workflow 产品化体验上仍需继续收敛。
